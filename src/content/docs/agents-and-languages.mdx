Both agents and languages are data, not code. Adding a new one is a matter of editing the
catalog — see [Templates & templates.yml](/slopctl/templates/) — not recompiling slopctl.

## Supported agents

**Universal support**: a single `AGENTS.md` works with all agents following the
[agents.md](https://agents.md) standard:

- Claude Code (Anthropic)
- Cursor (AI code editor)
- GitHub Copilot (GitHub)
- Codex (OpenAI)
- Mistral Vibe
- OpenCode
- Pi (earendil-works)
- Kiro (Amazon Web Services)
- Goose (Agentic AI Foundation)
- Cline (Cline Bot Inc.)

One `AGENTS.md` for all agents. Agent-specific files (e.g. command prompts) reference
`AGENTS.md` when needed. Claude Code, GitHub Copilot, and Cursor additionally get a slim
redirect stub (`CLAUDE.md`, `.github/copilot-instructions.md`, `.cursorrules`), since each
auto-loads a file of its own before it would otherwise discover `AGENTS.md`; all three stubs
come from one shared template source.

The default catalog includes `init-session` support for every built-in agent: Claude,
Cursor, Copilot, OpenCode, Pi, and Kiro use their native command/prompt directories; Codex,
Vibe, Goose, and Cline use an `init-session` skill because those agents don't provide the
same recommended predefined prompt workflow.

Agent filesystem conventions — prompt directories, skill directories, workspace detection
markers — live in `agent-defaults.yml`, updatable independently with `slopctl agents --update`
without recompiling slopctl.

## Supported languages

The default [`templates.yml`](https://github.com/heikopanjas/slopctl-templates/blob/develop/templates/templates.yml)
is a starter catalog, not a hard-coded language list. It ships useful examples for common
languages, but language support is entirely data-driven.

Currently configured in the default template catalog:

- **C** — skills: `c-coding-conventions`, `cmake-build-commands`; config files:
  `.clang-format`, `.editorconfig`
- **C++** — skills: `cpp-coding-conventions`, `cmake-build-commands`; config files:
  `.clang-format`, `.editorconfig`
- **Rust** — skills: `rust-coding-conventions`, `rust-build-commands`; config files:
  `.rustfmt.toml`, `.editorconfig`
- **Shell** — shell scripting for bash and zsh; skills: `shell-coding-conventions`,
  `shell-build-commands`; no config files
- **Swift** — skills: `swift-coding-conventions`, `swift-build-commands`,
  `swift-concurrency-pro`, `swift-testing-pro`; config files: `.swift-format`, `.editorconfig`
- **SwiftUI** — includes all Swift skills and config files plus `swiftui-pro`

Coding conventions and build commands are installed as [Agent Skills](https://agentskills.io)
rather than fragments merged into `AGENTS.md`. A slim hint fragment is merged into
`AGENTS.md` to inform agents that skills are available.
