---
title: Agent Skills
description: How slopctl installs and routes Agent Skills across cross-client and native-only agents.
---

slopctl supports [Agent Skills](https://agentskills.io) — an open format for extending AI
agent capabilities with specialized knowledge and workflows.

A skill is a directory containing a `SKILL.md` file with YAML frontmatter (`name`,
`description`) and Markdown instructions. Skills can optionally include `scripts/`,
`references/`, and `assets/` subdirectories.

## Four ways to define a skill

1. **Per-agent** in `templates.yml` — `source` under `agents.<name>.skills` (installed to the
   agent-specific skill directory)
2. **Per-language** — `source` under `languages.<name>.skills` (installed to cross-client
   `.agents/skills/` for cross-client agents)
3. **Per-shared-group** — `source` under `shared.<name>.skills` (propagated to including
   languages via `includes`)
4. **Top-level** — agent-agnostic skills under the `skills` section (routing follows the
   smart default below)

All skill definitions use a single `source` field (GitHub URL or local path); the skill name
is derived from the source directory name.

- **Agent skills** (`agents.<name>.skills`) — installed to the agent's native workspace
  skill directory (e.g. `.claude/skills/`, `.codex/skills/`, `.cursor/skills/`), regardless
  of cross-client support
- **Language skills** (`languages.<name>.skills`) — distributed by installed agents: one
  shared copy in `.agents/skills/` when any cross-client agent is installed, one copy per
  native-only agent skill dir when native-only agents are installed, `.agents/skills/` only
  when no agents are installed
- **Shared group skills** — propagated to any language that includes the group via
  `includes`; same distribution rules as language skills
- **Top-level skills** — same agent-aware distribution as language skills; optional
  `target: '$userprofile'` installs globally (e.g. `~/.codex/skills`)

GitHub skills are cached during `templates --update` via one tarball download per repository
(not per file); `init` uses the same tarball path for URL-based skills not yet cached. Skills
are tracked with the `"skill"` category in the file tracker for modification detection.
Removing an agent (`slopctl remove --agent <name>`) also removes its skills.

| --- | --- | --- | --- |
| Cursor | `.cursor/skills/` | — | ✓ |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` | ✗ |
| Codex | `.codex/skills/` ¹ | `~/.codex/skills/` | ✓ |
| Copilot | `.github/skills/` | `~/.copilot/skills/` | ✓ |
| Mistral Vibe | `.vibe/skills/` ¹ | `~/.vibe/skills/` | ✓ |
| OpenCode | `.opencode/skills/` | `~/.config/opencode/skills/` | ✓ |
| Pi | `.pi/skills/` | `~/.pi/agent/skills/` | ✓ |
| Kiro | `.kiro/skills/` | `~/.kiro/skills/` | ✗ |
| Goose | `.goose/skills/` | `~/.agents/skills/` | ✓ |

¹ Codex and Mistral Vibe each scan both their native skill dir and `.agents/skills/`. slopctl
installs their agent-specific skills to the native dir; language and top-level skills use
`.agents/skills/` to avoid duplication with other cross-client agents.

## Skill routing decisions

| How the skill is defined / invoked | Agent context | Installed to |
| --- | --- | --- |
| `agents.<name>.skills` | named agent | agent's native workspace skill dir |
| `languages` / top-level `skills`, target `$workspace` or omitted | no agents installed | `.agents/skills/` |
| `languages` / top-level `skills`, target `$workspace` or omitted | cross-client agent(s) installed | `.agents/skills/` |
| `languages` / top-level `skills`, target `$workspace` or omitted | native-only agent(s) installed | each native agent skill dir |
| `languages` / top-level `skills`, target `$workspace` or omitted | mixed cross-client + native-only | `.agents/skills/` plus each native-only copy |
| `init --agent <native-only>` after language install | native-only agent added later | hydrates installed language skills into the agent's native dir |
| Any skill definition, `target: '$userprofile'` | any agent | agent's userprofile skill dir (global exception) |

## Examples

**Per-agent:**

```yaml
agents:
  cursor:
    skills:
      - source: 'https://github.com/user/cursor-skills/tree/main/create-rule'
        # skill name derived from source: "create-rule"
```

**Per-language:**

```yaml
languages:
  rust:
    files:
      - source: rust-coding-conventions.md
        target: '$instructions'
    skills:
      - source: 'https://github.com/user/rust-skills/tree/main/rust-analyzer'
```

**Shared group (propagated to including languages):**

```yaml
shared:
  cmake:
    skills:
      - source: 'https://github.com/user/cmake-skills/tree/main/cmake-skill'

languages:
  c:
    includes: [cmake]      # inherits cmake files AND skills
```

**Top-level (agent-agnostic):**

```yaml
skills:
  - source: 'https://github.com/user/cursor-skills/tree/main/create-rule'
  - source: 'skills/my-local-skill'
    target: '$userprofile'   # optional: global policy install (e.g. ~/.codex/skills)
```

## Agent directories

Agents can declare workspace directories that should be created during `init` — useful for
directories the agent expects to exist but that aren't tracked by version control, like
Cursor's `.cursor/plans`:

```yaml
agents:
  cursor:
    prompts:
      - source: cursor/commands/init-session.md
        target: '$workspace/.cursor/commands/init-session.md'
    directories:
      - target: '$workspace/.cursor/plans'
```

When you run `slopctl init --agent cursor`, `.cursor/plans` is created in the workspace
alongside the usual instruction and prompt files. If it already exists, the step is silently
skipped. Directories are also shown in `--dry-run` output. Each entry has a single field,
`target`, using the standard placeholders.
